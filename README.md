# 花间 · 自贡三人花麻将

Vue 3 + Vite 的三人联机本地候选版（0.6.1，部署状态以站点为准），只有条、筒，每种牌八张，共 144 张。含可关闭的角色语音、无广告、无充值、无现金赌注，只记虚拟积分。

这不是单机假联机：一个服务端负责洗牌、发牌、轮次、胡杠判定和计分。浏览器只收到自己的手牌，对手的手牌不会发送给客户端。三个浏览器连接同一台服务器即可一起打牌。

## Windows / macOS / Linux 启动

需要 Node.js 22.13 以上（推荐 Node.js 24 LTS）和 npm。

1. 下载此仓库并解压，或 `git clone https://github.com/wztxpp/flower-mahjong.git`。
2. 打开项目文件夹的终端，执行 `npm ci`。
3. 执行 `npm run dev`。
4. 打开 `http://localhost:5182/`。

开发端口固定为 **5182**，启用 `strictPort`。端口被占用会直接报错，不会悄悄换端口。

要运行构建后的版本：

```sh
npm run build
npm start
```

生产服务也默认使用 5182，可通过 `PORT` 环境变量修改。Windows PowerShell：`$env:PORT=5182; npm start`。

## 三个人怎么开始

- 第一人填落座名并建房，再把房间号或邀请链接发给另外两人。
- 另外两人打开**同一个服务器地址**，填自己的名字，输入房间号加入。
- 满三人后，房主点击开始。当前可操作的按钮由服务端返回。牌局结束后，房主可在同一个房间再开一局，无需重新邀请。
- 房主在每局开局前可选“胡后自动打出”，默认勾选；不勾选时，胡后没有胡、杠可选也须点“过”才打出新牌。已有合法杠仍必须杠。本局设置不可中途更改，刷新和重连会保留。
- 同一局可反复胡牌；三家都至少胡过一次，或牌墙耗尽时结束。新规则自动摸牌，胡过后只处理新摸牌。详细计番、碰杠优先级及暂定边界见 [规则说明](docs/RULES.md)。
- 旧版本已开局的房间继续保留原规则和牌局，不静默换规则。可点击“返回大厅 / 换桌”，安全离开旧桌后另建新桌。
- 带同一 `room` 参数的页面刷新会使用本标签页的对应凭证重连。没有 `room` 参数的主页始终进入大厅，不自动恢复旧桌。三人请使用各自的浏览器或设备，不要分享座位或个人记录凭证。
- 大厅展示本人的累计已结算虚拟积分及每局记录，未结束的牌局另列暂记积分。身份由浏览器保存的随机凭证识别，不按昵称合并。数据存在服务器；清除浏览器数据会失去访问凭证，其他设备不会自动同步，当前没有跨设备找回功能。房间号不是座位凭证。

同一 Wi-Fi 下：其他人访问启动电脑的局域网地址，例如 `http://192.168.1.23:5182/`（请换成实际地址）。如果系统防火墙询问，只对可信的私人网络允许。`localhost` 只代表当前设备，不能发给另一台手机当作服务器地址。

仓库上传不等于互联网托管。跨网络三人联机需要运行同一个后端服务，不能仅上传静态 `dist` 到 GitHub Pages。当前公开托管版无需平台账号登录；房间仍需要各自的座位凭证。项目不自行注册付费服务。

## 已实现

- 三个座位原子落座，房主控制开局，名字校验；座位满员和重复点击受保护。
- 144 张牌完整守恒；服务端判牌和合法动作校验；私有手牌、暗杠隐藏。
- 公开剩余牌数、弃牌、萝卜、碰杠、每人的胡牌区、积分和操作记录；一炮多响的逻辑副本不算额外实体牌。
- 碰、明杠、暗杠、补杠、四张杠加第五张，以及逐次杠积分；反应结束后胡优先于杠、杠优先于碰，同级按顺位。
- 胡牌后的固定手牌、连续自摸、自动摸打和杠后特殊出牌；三家胡牌后原子结束。
- 全桌首次胡翻六张共享萝卜，每次杠另翻一张；萝卜乘法计分，神龙 6/7/8 张在终局各收 10/20/40 分。
- 一至四番为1/2/4/8分，五番起每番加2分；每次胡按本人的手牌、碰杠和胡牌区计算四张/五张/六张同牌加番。
- 手机与桌面响应式、传统图案条筒、黑八筒、私有胡牌诊断、重连和版本冲突保护。
- 当前回合操作直接返回权威状态，版本未变时只传轻量回复，减少等待和重绘。

## 进出房间与个人记录

- 未开局离席释放本人座位并交接房主；进行中的局只标记离席，不清空手牌、不代打、不破坏其他玩家的牌局。
- 离席时停止本页旧轮询。牌局可能等待离席者通过原房间链接重连，不会擅自跳过他。
- 每局稳定标识避免重复计分。旧版本只迁入仍有本人座位凭证可验证的现存记录，不虚构早已被覆盖的旧局。
- 具体生命周期、数据限制与回退说明见 [房间说明](docs/ROOM-LIFECYCLE.md)。

## 服务端与隐私

本地模式使用单进程 Node HTTP 服务，状态存到 `.data/rooms.json`，匿名身份索引存到 `.data/profiles.json`。文件包含私有牌局状态和座位凭证的 SHA-256 摘要，不包含明文凭证。不要共享 `.data`，不要提交到 Git，也不要将它当静态文件托管。本版不自动清除历史房间，离席不删除积分或操作记录。

同一份 `.data` **只能由一个进程写入**。开发模式与生产模式不要同时启动。部署为多个服务器实例时，应使用支持原子 compare-and-swap 的数据库；`server/store.js` 的 D1Store 和 `server/worker.js` 提供 Cloudflare Workers 对应实现。托管数据库表见 `docs/DEPLOYMENT.md`。普通 Node 模式重启会恢复已保存的牌局。

通信在可信的本机/局域网开发时可用 HTTP；互联网部署必须使用 HTTPS，避免座位凭证被截获。此首版没有账户系统、旁观入口、踢人或防作弊联盟检测，适合熟人试打。

## 规则边界

按用户口述制作，不宣称代表统一的“自贡标准”。尚未明确的特殊对子牌型加番、七张以上同牌加番、历史胡牌区的萝卜匹配、部分付款边界和大单钓叠加，保留为明确的暂定行为或配置，不声称已得到口述确认。见规则说明和 [反馈核验记录](docs/PLAYTEST-CHANGES.md)。

## 角色语音（0.5.0）

- 落座时可选小桃（萝莉音）、清岚（御姐音）、晴禾（阳光少女音），也可选随机。开局时服务端分配三位不同角色；偏好冲突从同选者中随机选一人，其余获得空余角色。
- 本局角色按服务端座位保存，所有客户端一致，刷新不会换角色。已存在的旧局采用兼容映射，不清空牌局或改变计分规则。
- 每个角色 23 条独立音频：一至九条、一至九筒、碰、胡、杠、自摸、放炮。胡牌先按服务端来源播“自摸”或“放炮”，再播“胡”；杠后接炮属于放炮。只对服务端已确认的出牌和碰胡杠播报，不朗读摸牌、手牌或等待中的申请。
- 首次点击页面解锁声音；右上角可关闭或重新开启。刷新、重连、切回页面不补播历史；音频串行播放，旧队列过期丢弃，离桌和静音立即停止。
- 图片为原创生成成年人物；声音为原创合成角色，不模仿具体真人。来源、模型、生成参数与校验结果见语音资产清单。

## 特殊牌型（0.6.0）

- 七对首胡后可胡初次完整牌型的全部牌种。3 番为基础，每组四张及以上加“张数 − 3”番；清一色再加 2 番，清七对为 5 番 10 分。后续固定该总档位，不因胡牌区积累再加番，萝卜每次重算。
- 大单吊先胡一次后，原单张及碰杠区牌种均可胡；同种牌可碰两次，保留为两组。大单吊和对对胡互斥，各加 2 番，清一色可另加 2 番；正常累计同牌番与萝卜。
- 杠后下一张弃牌不会再被重复接胡锁误拦截；普通弃牌的原有接牌限制不变。
- 新牌型规则从下一局启用。已有牌局保留开局时规则、手牌和旧账，页面会提示；不会回补已经错过的胡牌或修改历史分数。
