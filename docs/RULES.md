# 三人花花麻将：当前可配置的试行规则

这是根据本次口述实现的**可试玩版本**，不是对自贡所有线下玩法或正式地方规则的认定。口述未确定的细节标为“试行约定”，集中保存在 `shared/game.js` 的 `DEFAULT_RULES`，方便之后按实际牌桌习惯修改。积分仅为本局虚拟分数，不涉及充值、付费或现金结算。

## 1. 已实现的核心规则

- 三位玩家，只有条子和筒子，各一至九。每种牌八张，共144张。
- 内部牌编号0–8表示一至九条，9–17表示一至九筒。编号不是实体牌唯一标识，但任何时刻每种牌严格保有八张。
- 三人各13张，0号位为庄家多发1张并先出牌。普通回合按0→1→2→0轮转。
- 胡牌不离桌、不结束牌局，可以继续多次胡牌。牌墙用尽才结算结束。
- 第一次胡牌从牌墙尾部翻六张“萝卜”；每次明杠、暗杠、补杠都从尾部翻一张萝卜，再补摸一张牌。
- 萝卜按数量相乘计分，例如手上同一种牌两张、萝卜同一种牌两张，萝卜加分为2×2＝4。
- 自己持有的同一种牌，手牌、已组成的碰杠和萝卜合计达到6/7/8张时，神龙加分分别为10/20/40。
- 自己胡过之后，普通打出的牌别人不能接胡；杠后的下一次出牌仍可由别人接胡，并按自摸结算。
- 多次胡牌有“叫牌”限制，不能不改变局面就反复点击胡牌取得分数。

## 2. 试行约定：需要按实际习惯确认的部分

### 胡牌牌型

默认允许四组顺子或刻子加一对将，以及七对。碰杠算已完成的一组。顺子不能跨越条筒边界。七对中的四张相同牌按两对计算。没有吃牌、抢补杠、天地胡额外加番、缺门要求、查花猪或流局查叫等未明确提出的规则。

`sevenPairs: false` 可以关闭七对。

### 胡完以后如何继续摸牌

为了让实体牌守恒，并让继续游戏的手牌始终保持合法张数：

1. 自摸胡时，把本次刚摸到的那张和牌移入公开的“已胡牌”区，其余手牌保留。
2. 自己仍是下一位摸牌者，进行一次“胡后续摸”。胡不会直接自动摸下一张，需要提交摸牌动作。
3. 接别人打出的牌胡时，该牌只保留一份在弃牌区，标记胡牌者；不会把同一张实体牌复制进多个赢家手里。赢家手牌不变。
4. 一炮多响时默认都结算，按离出牌者最近的顺位安排先后，最近的赢家获得下一次续摸权。

这是一种可明确执行的试行处理方式，不代表口述已确认实体和牌应该如何摆放。

### 重复胡牌限制：默认到下一次普通摸牌解锁

每次胡牌时，保存“去掉本次和牌之后，这副牌能胡哪些牌”的完整叫牌集合。

- 胡后立即续摸，以及杠后补摸，**不会**解除锁定。
- 锁定期间，如果当前叫牌集合与上一次成功胡牌的集合有任意重合，不能再胡。
- 默认允许完全不重合的新叫牌集合提前胡牌。
- 当回合流转后，玩家下一次正常轮到自己摸牌时，解除锁定。即使叫牌完全相同，这次正常自摸也可以再次胡。
- 因此这不是“相同叫牌以后永远不能胡”。例如上次叫六条，胡后马上续摸六条不能重复胡；打出牌、轮过其他玩家，下一次普通摸到六条可以再胡。
- 玩家胡过以后，默认只允许不改变当前完整叫牌集合的杠。杠后补摸不会解除重复胡牌锁。

默认 `repeatHuLock: 'untilNaturalDraw'`。如果实际规则要求必须变叫才能重复胡，可以改为 `'untilWaitChange'`。`allowChangedWaitDuringLock: false` 可禁止锁定期内的变叫提前胡；`preserveWaitsOnPostHuKong: false` 可关闭胡后杠的保叫要求。以上开关用于修正试行解释，默认不会永久锁死同一叫牌。

叫牌集合只检查牌型和本人的手牌、已碰杠牌，不依据暗牌墙或对手手牌推断“活张”，避免泄露隐藏信息。

### 基础分、支付方和萝卜范围

默认单家应付分数：

`基础1分 + 萝卜相乘加分之和 + 神龙加分之和`

- 自摸：其他两位玩家各支付单家分数。
- 普通接炮：仅出牌者支付一次单家分数。只要出牌者尚未胡过，就允许别人合法接胡，包括别人的第一次胡。
- 杠后接炮：按自摸，另外两位玩家各支付单家分数。
- 所有分数严格零和；开启下一局时本局分数重置为0，不跨局累计。
- 每次胡都重新计分。第一次翻出的六张萝卜立即参与这次胡牌计分。
- 每次杠翻出的萝卜留下，之后每次胡都参与计分。杠本身不另收即时分数。
- 默认萝卜匹配数量包含自己的暗手牌和已碰杠牌。`radishCountsMelds: false` 可改为只匹配暗手牌。
- 默认神龙按自己全部持有牌计算，包含碰杠与萝卜；不同牌型的神龙分数相加。胡牌时的和牌也计入这次分数。`dragonCountsMelds: false` 可改为神龙只数暗手牌与萝卜。
- 默认 `stackDragonBonus: true`，神龙加分叠加基础分及萝卜分。若改为 `false`，结算取“基础分＋萝卜分”和“神龙总分”两者较高值，不叠加。这两个计分选项都是待确认的试行配置。
- `baseHuPoints`、`dragonPoints: { 6: 10, 7: 20, 8: 40 }` 均可配置。页面和分数不是现金金额。

### 碰杠、接胡和同时响应

- 对手打牌后，系统检查另外两位玩家是否能胡、碰或明杠。只有存在合法动作的人需要作选择。
- 所有有资格的玩家都必须选择操作或“过”；系统不会按谁点击得快决定结果，也没有离线自动过或超时抢答。
- 胡优先于碰和明杠。碰和明杠同级，发生竞争时按离出牌者最近的顺位决定。
- 默认 `multipleWinners: true`，所有选择胡牌的人都胡；设为`false`时仅最近的胡牌者结算。
- 中途响应不公开玩家选了什么；其他人只能看到哪些座位已经响应。
- 碰后直接出牌，不摸牌，不能把碰本身当成自摸胡。
- 暗杠、明杠、补杠都即时翻一张尾部萝卜，再从牌墙**头部**补牌。补牌后可以合法胡牌、再杠或出牌。
- 杠后的接炮标记持续到该玩家下一次出牌，包括在此之前发生的自摸胡和续摸；该次出牌之后标记清除。
- 保守试行：牌墙必须至少剩两张才允许杠，保证有一张萝卜和一张补牌。

### 最后几张牌

- 第一次胡时不足六张萝卜，就取走全部剩余牌。
- 同时多人胡牌时按固定顺位分配剩余萝卜，后面的赢家可能不足六张或一张也没有；仍然结算合法的胡牌，然后结束。
- 最后一张摸牌仍可以胡或出牌。最后一次弃牌也会等合法的接胡、碰或“过”解决后才结束。
- 胡牌把牌墙用尽时，先结算这次胡，再结束。所有已翻萝卜、已胡牌、弃牌和手牌均保留，不丢弃或复制实体牌。

## 3. 引擎与服务端契约

文件：`shared/game.js`，纯JavaScript ESM，不依赖Node专用模块或外部包，可供Node及Cloudflare服务端使用。

- `createGame({ seed?, rules? } = {})` 创建一局。`seed`仅供本地自动化测试复现，生产房间API不得接受客户端传入种子或牌墙。无种子使用Web Crypto安全随机洗牌。
- `applyAction(game, seat, action)` 返回新状态，不修改旧状态；非法动作抛出异常。
- `getLegalActions(game, seat)` 返回当前合法的具体动作数组，例如`{ type: 'discard', tile: 3 }`、`{ type: 'hu' }`、`{ type: 'pass' }`。
- `getPlayerView(game, seat)` 只生成该座位被允许看到的数据，不得把内部game对象直接发给客户端。
- `assertGameInvariants(game)` 验证144张牌、每种八张、手牌张数和零和积分。
- 辅助导出 `isWinningHand`、`getWaitTiles`、`DEFAULT_RULES` 方便自动测试。

支持动作：`draw / discard / hu / pass / peng / mingGang / anGang / buGang`。

回合状态：`phase: 'turn' | 'claim' | 'finished'`；普通回合有`turnStep: 'draw' | 'discard'`；服务端保存`currentSeat`、`revision`及所有私密状态。每接受一个动作，revision加一。服务端需要认证座位、验证客户端预期revision并串行化动作，避免重复请求或跨玩家操作。

玩家视图包含：

- `players[3]`的公开座位、手牌张数、已碰杠、萝卜、分数及胡次数；只有本人有`hand`数组。
- 对手暗杠的牌值隐藏，返回四个`null`，日志也不写暗杠的牌值。
- 公开弃牌`discards`、公开自摸和牌`retiredTiles`和中文日志`history`。
- 本人的`legalActions`、`waitTiles`、`lockedWaits`、`huLockActive`和`drawnTile`。
- `wallCount`，但绝不会返回牌墙顺序。摸牌日志不记录牌值。
- 接牌阶段只返回出牌座位、牌、待响应座位和已响应座位，不返回其他玩家的可选动作或已选动作。
- 胡牌日志提供`score: { base, radishBonus, dragonBonus, total }`、`payments`和`newRadishes`；不提供他人手牌逐张计分明细。

## 4. 验证

运行 `npm run test:rules`。覆盖牌型、非法动作、视图隔离、暗杠隐私、六张萝卜、各类杠、重复胡牌解锁、碰胡优先级、一炮多响、接炮支付、神龙6/7/8、牌墙末尾和状态序列化恢复。另模拟100局完整游戏，对每个动作检查全部牌张和积分守恒。
