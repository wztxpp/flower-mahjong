# 0.3 房间生命周期与个人记录

本次只修复进出房间、身份与记录，不调整麻将规则或现有牌局的规则版本。

## 问题与证据

- 0.2 页面初始化在地址没有 `room` 时仍恢复旧会话。2026-11-03 使用新建的生产测试桌复现：回到根主页后又显示旧桌，地址却仍是根主页。
- 原“换新桌”只清除客户端当前会话；服务端没有离席操作，也没有房主交接。
- 原历史只在当前房间的当前局中展示，重开一局会替换当前 `game`，没有按个人身份保存的跨局列表。
- 同期生产健康接口正常返回 200；检查到的错误日志没有 Worker 崩溃。一次读取取消不能单独证明用户具体网络故障原因。未读取或更改其他玩家的私有牌局。

## 入口约定

- 不带 `?room=` 的主页只显示大厅，不自动回旧桌，也不提供“恢复上一桌”按钮。
- 邀请链接指定哪个房间，就进入那个房间的入口；其他房间的旧凭证不会覆盖邀请。
- 同一房间的明确链接和已有座位凭证可以重新连接。房间号不是座位凭证。
- 退回大厅时停止旧轮询，取消在途读取，并忽略已经过时的响应。切桌不会关闭共享后端。

## 保护已有牌局

- 未开局时，离席只释放自己的座位，并把房主交给仍在桌内的人。
- 已开局且未结束时，只把本人标为离席，保留座位、手牌、积分、牌墙和操作记录，不代打、换人或重置牌局。轮到离席者时，牌局可能等待本人通过原链接重连。
- 已结束的局在下一局开始前保留历史记录。离席不是再次结算，也不把尚未结束的局假装成已完成。
- 其他房间不受切桌影响。数据库采用增量添加，不清空房间或旧日志。

## 匿名个人记录

- 个人记录由不可猜测的匿名浏览器凭证识别，不按昵称识别，因此同名玩家不会共用账本。
- 记录保存在服务器；浏览器只保存访问自己记录所需的凭证。大厅区分已完成局的累计积分与未结束局的暂记积分。
- 每局使用稳定标识，重复请求、刷新、离席与断线不会重复结算。
- 旧版本能迁入的只有仍有本人有效座位凭证证明的现存记录。旧版本已经被覆盖、没有保留的历次牌局无法凭空还原，不按昵称猜测归属。
- 没有强制登录，也没有手机号、密码、付费或现金交易。清除浏览器站点数据会失去匿名访问凭证；另一设备或另一浏览器不会自动同步身份。服务器仍保存记录，但首版没有跨设备找回功能。

## 回退与验证

部署仍使用原公开站点和数据库绑定。新增数据字段与表向后兼容，原版本可回退；回退不会自动删除本轮新增的个人记录。回退到旧前端会重新带回旧入口行为，不应作为常规使用方式。

具体验证结果见 [本轮专项验收](ROOM-RECOVERY-QA.md)。原麻将规则、私密手牌和三人联机回归继续执行。

### 当前规模边界

历史摘要和公开事件目前随房间 JSON 保存，未人为截断；长期在同一房间玩很多局会使读取与写入变大。后续规模扩大时需要独立归档和分页，但不能以清空历史作为优化手段。首次建房或加入若服务器已提交而网络丢失了整个返回包，客户端不会擅自重发；没有拿到的新座位凭证无法由当前前端补偿离席。已有座位的中断离席则保存待处理意图，刷新后仍会继续安全确认。
