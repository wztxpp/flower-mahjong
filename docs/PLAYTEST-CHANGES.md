# 试玩反馈与修订边界

日期：2026-11-03。所有分数都是本局虚拟积分。

## 已核实的旧版问题

- 胡过后仍能打任意手牌：已在旧版引擎内存局面复现，属于服务端合法动作限制缺失，不只是按钮问题。
- 普通摸牌需要手点，成功操作后还立即再发一次完整查询；轮询每次响应后再等一秒。修订自动摸牌、权威操作响应复用、轻量版本查询和自适应轮询。
- 没有个人胡牌区；自摸实体和牌只保存在后台，接炮仅在出牌者牌河打“胡”标记。
- 未实现即时杠分、第五张杠、三家都胡即结束、胡杠同时出现只给胡、胡过后的出牌不可碰。
- 原先碰与明杠同级；最新明确规则是胡优先、杠高于碰、同级顺位最近者优先，且必须等所有可回应者操作完。

## 萝卜反馈：未证实旧版数据丢失

旧版每次合法杠已立即追加一张萝卜，首次胡再追加六张，并没有清空旧萝卜。用守恒的内存牌局验证，一杠后首胡为七张、两杠后首胡为八张；胡牌日志只显示“本次新翻六张”，与总数容易混淆。本次补充累计展示与回归测试，不能把用户那局未经定位的“少萝卜”直接判定为同一原因，也不能将总数硬编码为八。

## B 的胡牌按钮问题：原现场仍未定位

用户报告 B 有筒子可胡但未出现按钮。没有该局的房号或当时截图，不能确认具体牌值、手牌、碰杠、叫牌锁、出牌者保护和响应状态。没有读取其他房间的暗牌来猜测。

新增自己的胡牌诊断和正反例测试，区分牌型、重复胡锁、受保护出牌、回合和已回应状态；它们不证明原现场已经复现或根因已解决。诊断只出现在本人的授权视图，不公开对手暗牌。历史私密摸牌不记录具体牌面，因此走过的局面未必能仅凭日志还原。

## 尚待按实际桌规调整

- 萝卜先按各自的杠累计，不替其他玩家累计；“所有杠”是否全桌共享尚不明确。
- 四张同牌加一番，五张加两番；六张以上同牌不推导新的加番表。神龙六/七/八张十分/二十/四十分保留为另一项。
- “对子牌型”的额外番没有明确口述数值，不另加。七对是否作为可胡牌型，与是否额外加番是两件事。
- 大单钓先按胡前只剩一张暗手牌判定，每家固定五十分；与一般番分、萝卜、神龙如何叠加采用明确的可配置暂定处理。
- 同时能胡能杠只给胡；是否连“过”也禁止未明确，先允许放弃胡。
- 三家同时达到已胡条件，先完成同次所有胡牌与支付，再结束，不能提前终止第二位赢家。

## 版本安全

0.1 的已保存牌局使用保留的原引擎继续，不修改旧手牌、牌墙、积分或操作记录。新局使用 schemaVersion 2。数据库无需破坏式迁移；同一站点、同一表保留旧记录。新规则只在新局生效，不能声称旧局已经悄悄变成新规则。
