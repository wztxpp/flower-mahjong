## 必须保持的行为

### 入口和切桌

- 主页始终显示大厅，不自动进入旧桌，也没有“恢复上一桌”按钮。
- 邀请链接中的房间优先于旧的活动会话。只有目标房间的已有座位凭证可以明确重连该房间。
- 同一房间参数刷新会恢复该座位；无凭证时不能仅凭房间号或同名身份接管座位。
- 回大厅立即停止旧轮询、取消旧请求、关闭弹层、释放焦点，并清理旧忙碌状态与选牌。
- 延迟轮询、动作、建房与重连回复不能重新打开已离开的牌桌。
- 离桌通知失败时保留待确认离桌意图；刷新主页后重试，确认前不能建立下一桌。
- A 桌 → 大厅 → A 桌的快速导航中，旧重连回复的补偿离桌不能断开最新选中的同一座位。

### 房间与凭证

- 等待开局或已结束时离桌释放本人座位，房主移交给仍在桌上的玩家。
- 进行中离桌只标记本人离桌；完整牌墙、手牌、积分、当前回合、胡杠状态和原规则均原样保留，不自动出牌或删除牌局。
- 离桌座位不能继续轮询、操作或开局；使用该桌的原座位凭证明确重连后才能恢复。
- 所有人离桌时房主为空；有人恢复后重新选定房主。
- 旧座位凭证不能读取、恢复或操纵替补玩家。重复离桌可幂等返回成功，但不会再次修改新座位或增加离桌日志。
- 旧轮询即便在离桌前通过鉴权、在离桌后才写心跳，也不能复活离桌玩家或覆盖新占用者。
- 离桌与开局并发时通过 CAS 顺序提交；若开局先成功，离桌安全重试并保留刚开始的牌局。
- 对一个房间的离桌和重连不修改其他房间。

### 个人历史和隐私

- 个人记录以随机匿名凭证绑定，不依赖昵称。同名玩家的记录互不混合。
- 历史读取使用个人凭证的 Authorization Bearer；房间轮询使用座位 Bearer；需要同时绑定两种身份的房间 POST 使用座位 Bearer 和正文中的 profileToken。
- 浏览器生成的身份在注册前保存；重复注册和两个独立 D1 处理器的并发注册只创建一个身份。
- 缺失、伪造或错误身份凭证不能读取历史；建房或落座提供了无效个人凭证时会拒绝，不会悄悄降级。未提供个人凭证的旧客户端仍可按原座位协议运行，但没有自动个人记录。
- 只有确实出示旧座位凭证的本人可以把旧房间当前可证明的一局绑定到自己的历史；同名和孤立索引项均不能授予访问权。
- 已结算累计积分与进行中、已离桌未结算积分分开。重连、重试、下一局和替补均不重复结算，不转移旧玩家记录。
- 每局记录含自己的座位、当时名字、分数、状态、参与者公开结果与操作事件；开局和结束事件各保留一次。
- 后加入已结束房间的人不能继承原玩家手牌、暗杠牌面、听口、胡牌锁定信息、积分或历史身份；原结算仍显示原参与者姓名。
- 历史和公开日志不包含凭证明文、哈希、牌墙、私有手牌或私有摸牌内容。
- FileStore 重开与新的 D1 处理器均恢复记录和离桌状态。历史不会因原七天房间窗口而丢失。

## 本轮发现并修复的边界问题

1. 已结束桌的替补座位原先仍可获得旧玩家暗杠和听口等私有字段。现已切换为中性展示并保留原局公开结算；独立回归已通过。
2. 离桌失败后刷新主页原先会丢失待处理离桌意图。现已持久化并在新落座前补完；组件回归已通过。
3. A → 大厅 → A 时旧重连成功的补偿离桌原先可能断开新的同一座位。现根据最新目标凭证判断；组件回归已通过。
4. 已离桌玩家在牌局结束后再次离桌需要释放座位，以及旧离桌座位首次绑定新个人身份，均有独立回归覆盖。

## 发布边界

- 发布需要同时应用 `drizzle/0001_hesitant_talkback.sql` 中个人身份和房间索引迁移，以及新的前后端；只更新静态资源不能提供历史接口。
- 未进行生产新版本写入测试，也未检查真实用户房间内容。发布后还需核验健康接口、静态资源版本和合成牌局。
- 匿名记录需要保留浏览器个人身份凭证；清除浏览器数据后没有账号找回机制。旧版本已经覆盖、且没有保存的更早牌局不能凭昵称重建。
- SQLite 适配器验证了实际 SQL 与独立处理器 CAS，但不替代真实部署的 D1 迁移、绑定及平台运行验证。
